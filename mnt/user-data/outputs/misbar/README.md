# مِسبار — أداة تحليل المتاجر والمواقع بالذكاء الاصطناعي

موقع Responsive جاهز للنشر يستخدم Google Gemini API (مجاني عبر AI Studio) لتحليل أي رابط متجر أو موقع وإرجاع تقرير عن:
التصميم والهوية، تجربة المستخدم، السيو والمحتوى، عناصر الثقة، وقابلية التحويل — مع إمكانية
مقارنة تلقائية بـ 2-3 منافسين حقيقيين في نفس المجال (نقاط القوة والضعف عندك مقابل عندهم).

## هيكل المشروع

```
misbar/
├── index.html          الصفحة الرئيسية
├── assets/
│   ├── style.css        التصميم بالكامل (Responsive على اللاب والتابلت والموبايل)
│   └── app.js            منطق الفحص والاتصال بـ Supabase Edge Function
├── supabase/
│   ├── functions/
│   │   └── gemini-proxy/
│   │       └── index.ts   Supabase Edge Function يخبي مفتاحي Gemini على السيرفر
│   └── README.md          خطوات نشر الفنكشن على Supabase
└── README.md
```

الموقع نفسه (index.html/assets) **Static بالكامل** وتقدر تنشره على GitHub Pages أو أي
استضافة ثابتة زي الأول. الفرق إنه مبقاش فيه أي حقل لإدخال مفتاح API — المفتاحين محفوظين
كـ Secrets على مشروع Supabase (Edge Function بسيطة)، والموقع بيكلم الفنكشن دي بس، وهي
اللي تكلم Gemini. المفتاح ميظهرش لأي زائر للموقع خالص.

## كيف يعمل الفحص تقنيًا

1. المستخدم يدخل رابط الموقع بس (مفيش مفتاح API مطلوب منه)، والأداة تجيب نسخة نصية من
   الصفحة عبر خدمة [Jina AI Reader](https://jina.ai/reader) (`https://r.jina.ai/<url>`) —
   مجانية ومفتوحة، وبتحل مشكلة CORS اللي بتمنع قراءة أي موقع مباشرة من المتصفح.
2. لو خيار "قارن تلقائيًا مع المنافسين" مفعّل (مفعّل بشكل افتراضي): الأداة تطلب من الـ Worker
   يستدعي Gemini مع أداة **بحث جوجل المدمجة (Grounding with Google Search)** عشان يلاقي
   2-3 منافسين حقيقيين في نفس المجال **مع سبب واضح لاختيار كل واحد فيهم**، وبعدين تجيب نسخة
   نصية من كل موقع منافس (بنفس طريقة Jina Reader).
3. النص المستخرج (وموقع كل منافس لو موجودين) يُرسل عبر الـ Worker إلى Google Gemini API
   (`gemini-2.5-flash-lite`) مع طلب صريح بإرجاع تقرير بصيغة JSON منظمة (نتيجة عامة، محاور،
   نقاط قوة وضعف، توصيات، ومقارنة بكل منافس لو طُلبت)، باستخدام
   `responseMimeType: application/json` عشان نضمن رد JSON صافي بدون Markdown fences.
4. الـ **Supabase Edge Function** هي اللي تحمل مفتاحي Gemini (كـ Secrets، مش في الكود)
   وتنادي API فعليًا؛ لو مفتاح رجع خطأ كوتة أو صلاحية، الفنكشن تجرب المفتاح التاني
   تلقائيًا من غير ما المستخدم يحس بحاجة.
5. الواجهة تعرض النتيجة كداشبورد تفاعلي، بما فيه قسم مقارنة المنافسين (مع سبب اختيار كل
   منافس)، وجنب كل نقطة (تشخيص محور، نقطة قوة/ضعف، توصية، مقارنة منافس) زر **"مش موافق
   على النقطة دي؟"** — المستخدم يكتب اعتراضه، والأداة تبعته للذكاء الاصطناعي يراجع النقطة
   تاني بناءً على محتوى الصفحة الفعلي، ويرد هل يتفق مع الاعتراض ولا لأ ومع الشرح.

## تشغيل محلي

مفيش تثبيت مطلوب للموقع نفسه. افتح `index.html` مباشرة في المتصفح، أو شغّل سيرفر بسيط:

```bash
python3 -m http.server 8000
# أو
npx serve .
```

ثم افتح `http://localhost:8000`. لازم بس تكون عملت نشر للفنكشن الأول (شوف
`supabase/README.md`) وحدّثت رابطها في `assets/app.js`، وإلا الفحص مش هيشتغل.

## إعداد المفتاحين (خطوة لمرة واحدة)

مفتاحي Gemini بتوعك بيتسجلوا كـ Secrets على مشروع Supabase، مش في أي ملف من ملفات
الموقع. اتبع الخطوات بالتفصيل في [`supabase/README.md`](supabase/README.md).

طبقة Gemini المجانية (Free tier) بتوفر عدد طلبات يومي لكل مفتاح؛ استخدام مفتاحين بالتبادل
بيدي مساحة أكبر قبل ما توصل للحد اليومي، ولو احتجت حجم استخدام أكبر تقدر تفعّل الفوترة
(Billing) على المفتاحين من Google Cloud Console.

> ℹ️ **ملاحظة:** الفحص الواحد بياخد طلب API واحد لـ Gemini. لو خيار "قارن تلقائيًا مع المنافسين"
> مفعّل، بيضاف طلب تاني لاكتشاف المنافسين، فيبقى إجمالي 2 طلب API بدل 1 للفحص الواحد.

## النشر على GitHub Pages

1. ارفع الملفات لريبو جديد على GitHub.
2. من إعدادات الريبو → **Settings → Pages**.
3. اختار **Branch: main** والمجلد **/(root)**، ثم احفظ.
4. الموقع هيبقى متاح على رابط من نوع:
   `https://<username>.github.io/<repo-name>/`

## التخصيص

- الألوان والخطوط كلها معرّفة كـ CSS variables في أول ملف `assets/style.css`.
- محاور التحليل (الخمسة) تقدر تعدّل عددها ومحتواها من الـ `system prompt` في `assets/app.js`
  داخل دالة `runAnalysis`.
- النموذج المستخدم `gemini-2.5-flash-lite` — قابل للتغيير من ثابت `MODEL` في `assets/app.js`.
  لو استخدمت alias زي `gemini-flash-latest` وواجهت مشاكل توفر (503) أو رفض للموديل (404) قدام
  مفتاحك، الأفضل تثبّت اسم موديل معيّن شغال عندك بالفعل — راجع القائمة الحالية على
  [ai.google.dev/gemini-api/docs/models](https://ai.google.dev/gemini-api/docs/models).
